## Lifecycle, freshness and action boundary

States: evaluating, pending_review, accepted, dismissed, deferred, stale, failed. Decisions bind exact versions and current CRM write authority. Deferred means explicitly revisit later; no scheduler, automatic resume or external notification. Existing security audit stores each safe transition/actor; recent recommendations have bounded keyset history. The table retains source fingerprint, knowledge version, trigger/context identifiers and reviewing actor/time, not another conversation copy. AI run stores the existing bounded result/evidence/proposal.

Every action rechecks current source, active contact/lead relationship and knowledge version. Settings locking plus existing organization-scoped communication advisory locking orders decisions against delivered-message insertion/status changes; contact/lead share locks order CRM edits. A tiny delivered-message trigger takes that existing advisory lock, with no AI call or history scan in ingress. Worker result mapping does not acquire the communication lock or run another job. Freshness is checked again before human action even if a result completed earlier. Stale history is displayed without rewriting accepted/dismissed decisions.

Accept/dismiss/defer have no communication side effect. Explicit **Accept and prepare draft** (or prepare after acceptance) can call only existing `communication_manage(...,draft,...)`, using the saved proposal, conversation channel and original inbound sender, after verifying the sender still belongs to the saved contact and existing recipient eligibility/consent/suppression. No recipient/tool/action name comes from model text or request payload. Draft identity is stable per recommendation; repeated preparation returns the saved draft and cannot overwrite human edits. Decision plus draft/audit commit together; failed preparation rolls back and is not shown accepted/completed. The existing AI save endpoint refuses to bypass review for orchestration runs. Separate exact-version administrator approval and mock delivery remain mandatory.

## Implemented verification and operating limits

The additive migration and a narrow AI-history-link delta were rehearsed and applied only to the preserved loopback stack. Existing public RPC signatures/types remain unchanged. The existing AI JSON response adds an optional `recommendation_conversation_id` so lead/Agents history directs orchestration results to review instead of offering a bypassing save control. The ordinary AI draft-save path refuses orchestration-owned runs; the recommendation helper invokes the same existing communication draft operation only after current review/freshness/eligibility checks.

All relevant local gates passed; [the report](../phases/phase-08-report.md) records actual counts, corrections, hashes and browser evidence. Existing qualification escalation remains conservative: unknown service/area, unfulfilled required business answers or configured restrictions/escalation may force HUMAN_ATTENTION rather than ASK_FOR_INFORMATION. These gates were not weakened. PREPARE_FOLLOW_UP and NO_ACTION mappings are contract-tested; the actual browser walkthrough exercised ASK_FOR_INFORMATION and HUMAN_ATTENTION.

Context remains the existing six delivered, tenant/contact/lead-scoped messages with each body truncated to 600 characters. Late linking increments the conversation revision even if that message falls outside those six, invalidating earlier review. History pages contain 20 recommendations; each references its existing bounded AI run, without copying conversations or prompts. Deferral has no timer. Re-evaluation is an intentional new request for changed source or a failed attempt, subject to existing queue/daily/concurrency limits; duplicate concurrent source requests share one logical result.

Retained decisions and unapproved drafts remain historical artifacts after later source changes. Staleness blocks a **new recommendation action**; it does not retract a separately reviewed, saved communication or replace Phase 04's approval policy. Owners must review the saved wording and recipient again before approval. There is no recommendation deletion/export, timed resumption, automated scheduler, external escalation or production rollout in this phase.
